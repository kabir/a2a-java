**R2 · P1 · Envelope creation, processing and correlation ownership are independent.**
`EventQueue.java:247–254`, `ProposalEventQueueItem.java:12–15,32–34`, `ExecutorSubmissionService.java:95–113,159–189,211–227`.

Give the queue an opaque per-submission capability containing the validated proposal and its own completion state. Claim processing once before touching the authority and settle that exact object. Test unregistered, different-payload same-ID, duplicate/replayed and delayed old envelopes, including after eviction.

**R4 · P1 · Observation timeout can arrive at the sink after a final success, and callback backlog defeats the configured deadline.**
`ExecutorSubmissionService.java:120–138,177–190,256–263`, `ExecutionProposalContext.java:38–40,61–68`.

With the common pool occupied, a separate probe left a 50 ms observation pending after 300 ms. A later authority finish can suppress a timeout that was already due. The final task completes the eventual future before completing the observer future or invoking the sink. A synchronous dependent on the eventual future can wait for the observer future or sink on that same worker and prevent both, with the timeout suppressed by `finished`. T04's finite observation and local delivery contract requires distinct timeout and authority states, with observer timeout leaving eventual evidence intact. Resolve the timed observation independently of listener backlog and serialize or suppress timeout notifications so they cannot supersede a final outcome. Preserve off-processor delivery. Reuse the two latch traces and test listener and stage continuations that refresh, resubmit, and await an independently delivered result. The existing asynchronous `thenCompose` test remains useful.

### Remaining findings

**RR1 · P1 · A typed queue failure can still report known non-commit after actual dispatch.**
`ExecutorSubmissionService.java:142–154,254–265,295–300`, `EventQueue.java:273–287`. The queue adapter forwarded the registered capability to a real child and then threw `EnqueueTimeoutException`. With the processor paused, the observed stage returned `KNOWN_NOT_COMMITTED`. Starting the processor led the same capability to the injected authority, which wrote to the in-memory store. The definitive failure had already occupied lookup. The capability's processing gate checks a claim flag and exact registration, but the terminal failure leaves it claimable. This violates T04's certainty contract. The exception type is public and can describe a custom queue's failure after forwarding. Base known non-admission on an atomic pre-dispatch decision from the owning queue/capability. Treat ambiguous forwarding as indeterminate and preserve eventual authority evidence. Exercise both typed exceptions after forwarding, alongside the existing real capacity-timeout test.

**RR2 · P1 · The local sink can drop authoritative failures and deliver an obsolete observation after the authoritative result.**
`ExecutorSubmissionService.java:166–172,304–324`, `ExecutionProposalContext.java:84–103`. The sink guard treats any result whose cause is `TimeoutException` as an observer timeout. In the probe, an injected authority returned an indeterminate `Failed` with that cause. Legacy `addTask` then left `lastProposalResult()` null and its listener was never invoked, even after the processor handled a follow-up event. With two listeners and an actual observer timeout, the second listener independently recorded `Committed` followed by `Failed`: the first listener held the timeout iteration while a concurrent worker delivered the authoritative result to both listeners. The current single-listener test only checks the latest stored value. An arbitrary dispatch failure also uses a separate observed-only sink dispatch without an authoritative-result guard. T04 requires the authoritative outcome to reach the void sink and forbids stale timeouts presented as later results. Distinguish observer/admission notices from authoritative results in internal state. Guarantee consistent per-submission listener delivery, including around slow listeners, without coupling either stage's completion to listener code. Test a real authority timeout cause, an uncertain forwarding notice followed by a result, and the two-listener interleaving.

**RR3 · P1 · Client continuations can occupy all timeout scheduler threads.**
`ExecutorSubmissionService.java:36–38,160–173`. The deadline job directly calls `submission.observed.complete`, which can run already-attached synchronous continuations on that timer thread. Four such continuations held all four workers. A fifth submission with a 250 ms deadline remained incomplete 750 ms later and resolved only after the other callbacks were released. This moves the contention from the common pool to the timer and violates the finite observation deadline even with idle authority processing. Make the deadline decision independent of user callback execution and ensure pending deadline work can progress when unrelated callbacks block. Retain the separate exact authority evidence and cross-channel wait coverage.

**RR4 · P2 · Status-message payloads can mutate the proposal and base after capture.**
`ImmutableTaskCopy.java:24–43`, `TaskSnapshot.java:9–12`, `TaskProposal.java:12–15`, `TaskStatus.java:41`, `TimelineEntry.java:21`. The corrective copy rebuilds history, artifacts, and timeline message entries, but retains the top-level status and timeline status entries. Both can carry an ordinary Message with map/list metadata. Mutating a nested source list after capture changed the retained base status message and the proposed timeline status message in the probe. T04 requires the base to represent the original authoritative value at its revision. Copy status messages through the same payload-copy path and test top-level and timeline status messages independently. The existing top-level metadata test passes and does not exercise these branches.

**RR5 · P2 · Completed lookup entries can survive their retention window and exhaust capacity.**
`ExecutorSubmissionService.java:299–300,338–356`. The expiration condition treats strictly positive time readings as the completion sentinel even though completion is already tracked by `authoritativeResult`. With a permitted negative monotonic-clock origin, the probe completed an entry at −1000 ns, advanced to −1 ns with retention of 10 ns, and found that the expired entry still occupied the only slot. T04 defines bounded completed retention while preserving pending work. Use the state flag to identify completed entries and measure elapsed duration from the completion reading without relying on its sign. Parameterize the existing clock test with negative and zero readings.
