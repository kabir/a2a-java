## Behaviour
- **One envelope per committed batch.** `CommittedTaskBatch` (snapshot + events) is replicated as a single `ReplicatedEventQueueItem`
  (`ReplicatedEventQueueItem.committed(batch, epoch, originId)`), stamped with `a2a.task-store.writer-epoch` (shared constant
  `extras/common/.../WriterEpochProperty.NAME`; `JpaTaskMigration.NODE_EPOCH_PROPERTY` aliases it). `extras/common` still does not depend on server-common
  (`TaskFinalizedEvent.getCommittedBatch()` is an opaque `Object`).
- **Local publication.** `MainEventBusProcessor.deliverCommittedBatch` calls `EventEnqueueHook.onCommittedBatch` once per non-final batch when the hook
  `handlesCommittedBatches()`; the per-event `onEnqueue` is kept for hooks that do not. Terminal batches are replicated from `TaskFinalizedEvent`
  (JPA `JpaTaskMutationTransactions` now fires it with the original batch, store revision included), followed by an ordered poison pill.
- **Remote receipt.** A replicated item with a committed batch takes an early branch: delivered to local children/lifecycle only. No `mutate`,
  no `save`, no push admission, no webhook. Local items cannot carry a batch (`EventQueue.carriesUntrustedResult`).
- **Receive gates** (`ReplicatedQueueManager.acceptedByEpoch`): own-origin dropped; unversioned or wrong-epoch envelopes rejected (this covers delayed
  generation-0 replication after migration); bare events rejected under an epoch; a legacy-only node rejects envelopes.
- **Ordering/dedup** (`CommittedBatchSequencer`, bounded 64 pending / 64 delivered / 4096 tasks LRU): DELIVERED, DUPLICATE, STALE, BUFFERED,
  CONFLICT, OVERFLOW; the poison pill is deferred until the terminal batch has been delivered.
- **Legacy-only profile unchanged** (epoch null): per-event hook, synthesized status+pill on finalization, old constructors preserved. A new constructor
  takes `@Nullable Long writerEpoch`; the `@Inject` constructor reads the property from `A2AConfigProvider` and fails fast if an epoch is set while the
  task store is `InMemoryTaskStore`.
- `ReplicationStrategy.send(ReplicatedEventQueueItem)` default throws `UnsupportedOperationException`; implemented by `ReactiveMessagingReplicationStrategy`.
- Docs: `docs/content/dev/extra/replicated-queue-manager.md` "Committed replication (A2A 1.1 writer epoch)".

## Not claimed
- No real two-node / multi-instance Kafka / PostgreSQL evidence for committed replication (T13 owns it); multi-instance Kafka tests were not run.
- No broker fencing/authentication: the epoch stamp and origin id are self-declared; broker fencing is a documented operator precondition only.
- No exactly-once, receipts, outbox, replay or cursor recovery (Phase 4). Receiver failures are not retried: a batch is recorded as delivered
  before delivery, so a failed local delivery is not redelivered. Gaps/ stale batches are dropped, not fetched.
- No T11 webhook dispatch (only the originating writer's routing is preserved; remote copies never dispatch).
- `JpaTaskMigration`/`mutateInTransaction` shared-transaction path still has no production caller.
- JPA legacy `save` finals (no batch) send only a stamped poison pill with a warning under an epoch; remote subscribers do not see a terminal status for that path.
- Terminal batches are replicated only by stores that fire `TaskFinalizedEvent` with a batch (JPA mutate); a custom `AtomicTaskStore` replicates none.
- The Kafka `testA2AMessageReplicatedToKafka` failure is pre-existing and non-discriminating beyond line 175.
