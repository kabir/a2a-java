## Retained limits / NOT claimed

* **Commit-to-hand-off window (Medium, B4-2, production):** `localBegin` runs when the event-bus processor reaches the committed batch, i.e. after the database commit. If node B commits and publishes N+1 and A receives it before A's processor has registered its own batch N (an event-bus backlog), A could deliver N+1 before N. Test 3 pauses after `localBegin`; the claim is "never reversed while the local publication hand-off is in flight", not for the earlier commit-to-registration window. Closing it needs registration at commit time (T14 area); not done here.
* Stuck publisher: remote batches for that task are buffered (MAX_PENDING 64, then OVERFLOW; GetTask recovers). No release timeout. One un-guarded `cancelSubmittedFinalEvents()` call in the distribute catch can skip the release (not reproduced).
* Capacity loss (256 events / 4 MiB per-task pending cap) and the 30-s per-attempt deadline loss were NOT exercised live. Test 10's 40 s window is an observation past the deadline, not a loss assertion.
* Test 4 replays only already-delivered records (duplicate/stale); reordering with buffering is covered by the sequencer unit tests and test 3. Remote records never touch the store, so "store unchanged" there is structurally true; the discriminating evidence for epoch rejection is the receiver rejection log plus the M3b subscriber assertion.
* Test 7 duplicate-remote-record check is trivially true (replicated copies never dispatch webhooks). Test 9 shows no lane transition for the unconfigured generations; the claim is only that they were never dispatched and the lane starts at the registration cursor.
* "Documented lane recovery" = SPI Javadoc of `recoverQuiescedClaim` (caller must verify old outbound workers are quiescent); the admin route is a test route. No operator runbook is claimed. Generation 4/gap work retired by recovery is lost to webhook delivery; no durable delivery.
* Test 12 shows check-time refusal (writer epoch older than the stored epoch). Not the in-flight window the `JpaTaskMigration.activate` javadoc warns about; no database-level fence; a storage epoch is not a live executor-owner lease; no Phase 5 live routing; no Phase 4 replay/cursors.
* Broker fencing: ACL denial of the old principal plus receiver-side epoch rejection of a self-declared stamp. Not sender authentication. Broker fencing remains a documented precondition.
* GetTask in the fixture runs without authorization (`a2a.authorization.required=false`).
