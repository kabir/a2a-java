## Behaviour
- Row locked `PESSIMISTIC_WRITE`, planned, persisted and flushed in one transaction; slot `markCommitted` only after the transaction
  method returns (commit completed). Planner/reservation/serialization/constraint failures -> `TaskMutationNotCommittedException`
  (slot cancelled); any other failure (incl. commit-time) -> `TaskMutationOutcomeUnknownException` (slot cancelled, no rollback claim).
- Unchanged plan keeps revision, no slot. Legacy `save` rows get one revision under lock on first snapshot/mutation.
- Final-state mutation fires `TaskFinalizedEvent` inside the transaction (AFTER_SUCCESS observers run only after commit; none on rollback).
- Shared-tx path (`mutateInTransaction`) joins the caller's transaction with the JPA push-config store: both roll back together.
  Independent-store enrollment (T06) is unchanged: config stays visible after guard failure, concurrent config replacement survives.
- NOT claimed: writer fencing / migration (T09), committed replication (T10), PostgreSQL/Kafka cluster evidence (T13).
  `writer_epoch`/`migration_marker` are stored but unenforced.
