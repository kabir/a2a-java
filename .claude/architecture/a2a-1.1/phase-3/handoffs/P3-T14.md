## The bound (stated honestly)

Detection is scheduler + authority-read deadline, not instantaneous and not a delivery guarantee.
- A stranded watermark (authoritative head > last delivered generation, no later mutation) is first sighted within about one
  reconciliation interval + one read deadline (about 10 s with defaults) of the loss.
- The observation is closed by the first read at least the reorder-gap deadline (10 s) after the first sighting.
- Worst case with defaults is therefore about 30 s plus scheduler delay. A read that fails or exceeds the 5 s deadline closes the
  affected observations (`AUTHORITY_READ_FAILED` / `AUTHORITY_READ_DEADLINE`); a full buffer closes only that observation (`BUFFER_OVERFLOW`).
- Closure uses the binding's existing failure path: `InternalError("... call GetTask to resynchronize, then resubscribe if the task is not finished.")`
  via `ChildQueue.terminateObservation`. The text is "retry/resync needed"; it is NOT a new retryability guarantee, StreamError code,
  replay range, cursor or repeated-snapshot guarantee. Explicit `GetTask` returns the final state.
- Recovery creates no mutation, task failure, webhook or replication (asserted by `recoveryCreatesNoMutationTaskFailureWebhookOrReplication`).
- Broker fencing remains a documented precondition only.

## Retained limits (Low/Info, not fixed)

- Ordinary-send path (`onMessageSendStream` etc.) is NOT wired and there is no CDI auto-wiring; only `onSubscribeToTask` uses the reconciler, opt-in via the builder.
- Legacy bootstrap and non-batch events carry generation 0 and are ungated.
- A task deleted from the store while observed is never judged.
- `cancel(true)` does not interrupt a hung reader thread (the deadline abandons the read; the pool is bounded to 4 threads + 1024 queued reads).
- Any authority-read failure closes all observers of that task.
- The event sizer's JSON cost is paid per observer; the downstream tube buffer is not counted in the 4 MiB limit.
- A theoretical unsynchronised read of `observation` may see a duplicate of a covered event (never a loss); a close racing `installObservation` is benign.
- `InMemoryTaskStore.readSnapshot` performs a one-time baseline write for legacy generation-0 tasks, so "no mutation" holds for baselined tasks.
- `register()` rollback on a schedule failure has no dedicated test (Info).
- Broker fencing is a documented precondition. No replay/cursor (Phase 4) and no live routing (Phase 5).
