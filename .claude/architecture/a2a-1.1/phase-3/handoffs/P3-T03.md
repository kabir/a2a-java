## Interfaces and behavior

Added `CommittedTaskBatch`, an immutable envelope containing one `TaskSnapshot`
and its ordered committed events. It retains each event's generation position;
earlier events may precede the final snapshot generation. It does not fetch later
state or construct intermediate snapshots. Batch finality follows the accepted
T02 assessment that `TASK_STATE_UNSPECIFIED` is terminal; the shared enum was not
changed.

Added `OrderedTaskPublisher`. The atomic store's reservation callback receives
only the read-only `TaskCommitSlot`; the store retains and transitions its
private `Reservation`. The publisher records a per-task placeholder during that
callback and invokes delivery after commit, outside the store lock. If N is
committed but pauses before publication, N+1 remains queued behind N. A failed
reservation is discarded so it does not leave a permanent local hole.

`TaskManager.processCommitted` routes local atomic-store Task, status, and
artifact events through `TaskMutationAuthority` against the store's authoritative
snapshot. It does not plan from the cached TaskManager task. Existing append
semantics come from T02: the event retains the incoming chunk while the final
snapshot has accumulated artifacts. Planner rejection remains typed and does not
become a task-failure mutation. Legacy-only stores retain their existing
`TaskStore` path; arbitrary `get`/`save` calls are not wrapped as atomic support.
Already committed replicated copies retain their legacy stamped-event handling
for T10 to replace with its separate provenance/finalization contract.

`MainEventBusProcessor` publishes canonical committed events to subscribers,
local push delivery, and eligible replication hooks. Push calls retain the
existing per-task chain and receive the batch's matching final Task snapshot.
`MainEventBusProcessorCallback.beforePushNotification(CommittedTaskBatch)` is
the T11 admission seam: it receives that snapshot and every generation position
before any sender invocation, including positions that later have no matching
configuration. Terminal lifecycle and processing callbacks run only after all
events have been distributed to child queues. Semaphore release remains in the
outer `finally` path.

`doCancelTask` waits for event-consumption completion on atomic stores using the
configured consumption-completion timeout, then returns the authoritative
snapshot. It does not return a captured earlier Task if a multi-event terminal
batch is still being published. Cancellation rejects already-terminal tasks,
including `TASK_STATE_UNSPECIFIED`.

Direct Message and error/control events keep their established single-event
behavior. In particular, A2AError's existing failed-status persistence remains
separate from the error event delivered to clients; no additional persisted
mutation is created to force it into a task batch. The accepted terminal-state
guard was also applied to the legacy TaskManager transition check.
