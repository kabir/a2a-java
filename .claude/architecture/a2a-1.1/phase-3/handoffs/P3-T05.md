## Implementation

`TaskMutationPlanner` now normalizes a full Task against the immutable current snapshot. It preserves canonical history, timeline, user artifacts, and omitted metadata/artifacts; merges supplied metadata; ignores task, timeline, and artifact generation claims; stamps agent artifact changes in proposal order; rejects duplicate IDs and invalid origins; and plans the whole batch before the atomic authority commits it. Nonterminal batches place status/metadata observation before artifact updates. Terminal batches place artifacts before final status. Metadata-only proposals emit one synthetic status observation while preserving status message identity and history occurrence count. No-op proposals leave task, revision, generation, and publication unchanged.

Initial materialization carries the opening request input in the execution-local submission service until the atomic proposal commit. It commits the opening message once, deduplicates its ID in bootstrap history, retains other supported legacy bootstrap history, and does not fabricate timeline entries for that history. Existing matching-base equivalent/status-only proposal behavior and 0.3/1.0 response and webhook projections remain intact.

Production full-Task mutations continue through `ExecutorSubmissionService` and its capability-gated ordered queue path into `TaskMutationAuthority`/`AtomicTaskStore`; queue admission is not treated as commit. The Task/revision pair is checked together under atomic mutation. External stale input and a stale proposal following the same executor's acknowledged delta reject locally; the executor can explicitly refresh and rebuild, or use delta emission. Initial opening input stays request-local until commit. No ordinary-send persistence rewrite was started.

`AgentEmitter` documentation now shows a refresh/rebuild example built from the refreshed `base.task()`. Added `FullTaskProposalTest` and `ExecutorMigrationExampleTest`; updated the compatibility expectation for metadata normalization. `TaskManager.saveTaskEvent`, `ResultAggregator`, and `VersionedOutputProjector` were inspected and left unchanged: production proposals reach task mutation through the atomic ordered authority, and committed event items carry the final snapshot used by aggregation/projection.
