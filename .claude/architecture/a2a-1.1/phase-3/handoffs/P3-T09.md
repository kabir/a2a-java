## Behaviour
- No epoch row => legacy mode: nothing stamped or baselined (legacy-only deployments unchanged).
- Epoch activated (`activate(n)`, never decreases) => every write/delete/baseline by a node whose `a2a.task-store.writer-epoch` is absent or differs
  is refused (`TaskMutationNotCommittedException` for `mutate`, `TaskPersistenceException` for `save`/`delete`/`readSnapshot`-baseline).
- Under an active epoch a row without `migration_marker` is baselined once under `PESSIMISTIC_WRITE`: generation 0 -> 1; history, artifacts (absent
  role stays absent), metadata kept; no timeline invented; marker+epoch stored in columns, not Task JSON; revision advances only when the Task changed.
- A row with a marker whose Task generation is 0 => `TaskSerializationException` ("corrupt"); `readSnapshot` fails, `mutate` -> not committed,
  `save` refused; row bytes unchanged.
- `save` under an active epoch refuses to lower the generation of a stored task.
- **Storage enforcement** is database privileges only, shown on real PostgreSQL: old role `a2a_old` (owner of the legacy 6-column schema) loses
  INSERT/UPDATE/DELETE; PostgreSQL returns SQLSTATE 42501 for INSERT, UPDATE, DELETE, and for a delayed "reset to generation 0" UPDATE after migration.
  The epoch/marker columns are explicitly documented as cooperative among new binaries, not an old-writer fence.
