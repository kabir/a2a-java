```java
SendInputParams SendInputParams.from(MessageSendParams legacy);

record TimelineEntry(long generation, Payload entry) {
    sealed interface Payload permits MessageValue, StatusValue { }

    record StatusValue(TaskStatus status) implements Payload { }
}

    @Nullable Map<String,Object> metadata, long generation)
    implements StreamingEventKind, UpdateEvent, EventKind { }

    sealed interface Payload permits Send, Subscribe { }

    @Nullable String message, @Nullable String referenceId,
    @Nullable Map<String,Object> metadata) { } // separate from task event/error hierarchies
```

`SendInputParams` allows message-only, message+updates, or nonempty artifact-only input. Artifact-only identity comes from each update's existing `taskId`/`contextId`; require the same nonblank existing-task identity across updates. With a message, reject conflicting nonblank identities; permit opening-message updates' empty provisional IDs only as the pinned request shape permits. Never invent a task ID field to repair this schema. State/authorization/capability/origin acceptance remains server Phase 3. Ignore input event generation during wire encoding (and server decoding); do not validate supplied input generation as authoritative. Reject no message/no updates. Keep legacy `MessageSendParams` unchanged.

Append these model components, keeping every old constructor descriptor through overloads and every existing builder method:

| Type | New components / defaults for legacy construction |
| --- | --- |
| `Task` | `long generation = 0`, nullable `List<TimelineEntry> timeline`; absence does not allocate generation 1 |
| `Artifact` | `long startGeneration = 0`, `long endGeneration = 0`, nullable `Message.Role role`; preserve unspecified provenance, interpret absent origin as AGENT only at projection/policy boundary |
| status/artifact update records | `long generation = 0` |
| `MessageSendConfiguration` | nullable `Long ifGenerationMatch`, nullable `Integer timelineLength` |
| `TaskQueryParams` | nullable `Long currentGeneration`, nullable `Integer timelineLength` |
| `ListTasksParams` | nullable `Integer timelineLength` |
| `AgentCapabilities` | `boolean userArtifacts = false` (map absent proto optional false; no new live flag) |
| `TaskPushNotificationConfig` | nullable `String protocolVersion`; no client/store fallback filled here |

Preserve optional scalar presence with `has...()`; absent and explicit zero limits/guards/cursors must round-trip independently. Negative lengths reject; zero limits are valid. Do not invent stricter cursor/generation ranges beyond pinned requirements. Decode zero event generation faithfully for the later reliability rule.

Unknown timeline entries are absent from public `Task.timeline()` but their known generations survive in notes; do not manufacture gaps or synchronization. Empty payload without unknown-field evidence is malformed. Unknown protobuf oneof bytes with PAYLOAD_NOT_SET are ignored in 1.1; unknown JSON variant objects are ignored after envelope/discriminator validation. Multiple known payloads, bad known members, missing required fields and protocol errors are never rescued as unknown. `StreamError` is known/local even before Phase 5; no `ClientEvent` or task failure is manufactured for it. Ordinary callback APIs cannot route live local rejection: terminate that **unsupported ordinary operation** with a clear invalid-response error rather than silently swallowing rejection; live result routing is blocked until Phase 5.
