## Blocking finding

1. **P2 — A failed stream can deliver its terminal callback before an earlier event callback finishes.** `Client.consumeObservation` registers a `completion().whenComplete` handler at `client/base/src/main/java/org/a2aproject/sdk/client/Client.java:464-472` that calls the public error consumer for non-completed outcomes. `TransportObservation.finish` resolves `completion` before draining serialized subscriber signals (`client/transport/spi/src/main/java/org/a2aproject/sdk/client/transport/spi/TransportObservation.java:180-183`). A concurrent `fail()` therefore invokes the terminal callback while an `onNext` event consumer is still active. This breaks T6's terminal-after-stream-events callback order. A deterministic local probe against the current compiled classes blocked the public event consumer, called `observation.fail(...)`, and observed `terminalBeforeEventEnded=1, terminalObserved=true`; the event consumer was released afterward. Route terminal delivery through serialized subscriber `onError`/`onComplete` (or otherwise serialize completion with event dispatch), and add a race regression. The existing atomic terminal flag ensures at most one terminal callback but does not enforce ordering.
