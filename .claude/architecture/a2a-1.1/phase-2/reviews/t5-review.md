1. **P2 — A failed observation can leave its subscriber waiting forever behind a buffered frame.** In `client/transport/spi/src/main/java/org/a2aproject/sdk/client/transport/spi/TransportObservation.java:157-179`, `finish()` clears `pending` only for `CANCELLED`. Repro: create an observation with a subscriber that requests zero frames; call `markReady()`, `publish(frame)`, then `fail(error)`. `completion()` reports `FAILED`, but the subscriber receives neither `onError` nor `onComplete`; later demand can deliver the buffered frame before the error. A local source-file Java probe against current `target/classes` printed `failed: completion=FAILED, onError=0, detach=0`. The saved `TransportObservationTest` covers overflow outcome and invalid-demand serialization, but not this zero-demand failure path. Ensure failure/deadline terminal delivery does not depend on downstream demand for stale buffered frames; add a focused regression checking exact-once subscriber error and completion.

2. **P2 — The opening deadline and buffer overflow terminate locally without detaching the underlying read.** `TransportObservation.java:182-185` calls `finish(DEADLINE)` without `cancelAction`; `publish()` at lines 109-111 calls `fail()` on overflow, which likewise never invokes `cancelAction`. Only explicit `cancel()` at lines 127-131 detaches. Repro: create with an already expired opening deadline and a counting `cancelAction`; `completion()` reports `DEADLINE` while the count remains zero. The same local probe printed `deadline: completion=DEADLINE, detach=0`. An active transport read can continue after the finite local deadline or buffer limit, even though later frames are rejected. Add exact-once detachment on these terminal paths, retaining the original `DEADLINE` or `FAILED` outcome; test both and the cancel race.
