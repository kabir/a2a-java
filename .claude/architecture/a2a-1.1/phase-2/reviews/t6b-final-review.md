## Actionable findings

1. **P2 production defect, acceptance blocking — non-2xx status-aware SSE responses can exhaust client memory before REST error mapping.** `JdkA2AHttpClient.java:379-388` uses `BodySubscribers.ofString` for the entire error body. `VertxA2AHttpClient.java:481-499` calls `response.body()` with no limit. Both paths are used by status-aware GET and POST SSE in `RestTransport.java:248-263,794-848`; a peer can send an unbounded HTTP error body without ever sending an SSE frame, bypassing the bounded `TransportObservation` frame queue. Android's apparent 10 MB limit is insufficient for a single long line: `AndroidA2AHttpClient.java:179-198` calls `BufferedReader.readLine()` before measuring length; the status-aware branch calls it at `:303-310`. A peer sending one huge line therefore allocates that line before rejection. Cap bytes while reading, before materializing a full line/body, in all three HTTP clients. On overflow, cancel/reset/disconnect the response and signal one error; retain HTTP status and headers and either a bounded body prefix or an explicit body-too-large error. Keep ordinary small HTTP 409 `ErrorInfo` bodies available to `RestErrorMapper` for typed `TaskGenerationMismatchError`. Add targeted GET and POST status-aware SSE tests for each client with an oversized body including a no-newline case; assert bounded rejection, no SSE event, one terminal error, prompt read cancellation, status/headers, and unchanged typed small-body 409 behavior. The precise cap is an implementation choice; the finite cap and enforcement before allocation are the acceptance criterion.

2. **P2 acceptance-evidence gap — public REST completion/error/cancel race is unasserted.** The T6 per-binding acceptance bullet at `implementation-plan.md:252` explicitly requires a public `Client.builder(card)` controlled peer where completion, error and cancellation race, with at most one terminal callback and no later event callback start. `Phase2RestPublicClientTest.java:241-303` checks a normal finite stream and one successful terminal; `:305-366` checks held-open close and shared injected-client ownership. `Phase2PublicClientTest.java:390-589` covers raw finite demand, malformed frame/local rejection and close, while shared SPI tests cover observation ordering. None runs the public REST race required by the plan. Add a bounded public test that holds an event callback while a malformed/error or peer completion and `Client.close()` compete, then releases it and asserts one terminal callback and no event callback begins after terminal. This is a missing integration assertion, not a reproduced production race.
