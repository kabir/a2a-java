## Implemented minimal corrections, verification pending

Added a package-private `ProtocolVersionClientInterceptor`, installed on blocking and async stubs. It adds a public CallOptions tracer factory which examines every merged version value, rejects any conflict as `A2AClientException`, and collapses identical values to the pinned version. For ordinary `MetadataUtils` interceptors, that callback is later than metadata merging and earlier than physical transport stream creation. A private forwarding call catches a start failure, cancels the delegate to clean up retry-stream state, and rethrows the original failure. Public constructor/provider/SPI signatures remain unchanged.

Shared `A2AExtensionsInterceptor` now scans all incoming version values. Conflicts close before dispatch with FAILED_PRECONDITION and existing rich ErrorInfo reason VERSION_NOT_SUPPORTED; identical values collapse to one before context capture. Single/missing metadata preserves its existing behavior. This is defense in depth; server rejection does not substitute for client pre-I/O enforcement.

## Remaining supported-extension ordering decision

**The general promise is not yet enforceable against all ordinary public gRPC extension points using the existing opaque supplied Channel API. Do not mark that broader criterion closed or silently exclude it.**

The concrete additional demonstrator is `GrpcChannelMetadataTest#laterChannelTracerCannotOverridePinnedVersionBeforeUnaryIngress`. A legitimate supplied-channel ClientInterceptor calls public `CallOptions.withStreamTracerFactory`; that later factory appends version1.0 after the SDK's pinned1.1 factory has checked/normalized. The desired pre-I/O/no-ingress assertion is expected to fail; actual root execution is pending. This is not a hypothetical malicious Channel implementation.

Adding a second check in `ClientStreamTracer.streamCreated` can see mutations made by all factory callbacks, but is not a general ordering solution: `StatsTraceContext.newClientContext`, lines49–54, subsequently invokes each returned tracer's `streamCreated` in list order, and later tracers may also legally mutate the headers there. ClientStreamTracer's API expressly allows that mutation. The SDK is outside the supplied Channel's interceptor chain, and its immutable CallOptions offers no public operation to move the guard behind all factories that the Channel may later append. Rejecting every additional factory would also reject gRPC's own retry-buffer tracer and legitimate instrumentation, requiring a compatibility/design decision rather than a routine fix.

There is a separate source-confirmed late stage: `CallCredentialsApplyingTransportFactory` invokes channel/call credentials after factory construction, and `MetadataApplierImpl.apply`, lines66–78, merges their headers before the underlying transport stream is created. That stage has not been exercised in a new runtime demonstrator. Throwing from a late asynchronous tracing callback without controlled call cancellation/error completion is not a verified remedy and must not be introduced as a speculative guarantee.

No additional production change for these late mutation stages is authorized by this report. Root should present the concrete remaining failure and explicit choices to the user if it cannot preserve the approved full contract without an API/compatibility restriction. The standard MetadataUtils correction remains useful but is not sufficient evidence to close the unrestricted criterion.
