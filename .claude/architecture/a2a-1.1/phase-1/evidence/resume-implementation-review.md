## Test assessment and remaining coverage limitations

The raw Netty attack control is meaningful: the registered real LoadBalancerProvider creates a real custom final-slot tracer and the server observes the conflicting duplicate metadata. Before-construction rejection covers both selected versions and both injected values. Private resolver exclusion, cold and warm calls, unary and streaming calls, and real enterIdle recreation are exercised. The mutation stress test runs concurrent public registry registration/deregistration and validates accepted calls or the precise rejection reason.

Nonblocking limitations to retain in the evidence:

1. The twenty-attempt race test can pass with every attempt rejected. It is a useful stress probe, not a deterministic proof that the monitor prevents check/capture interleaving. The source argument supplies that proof, and the separate post-build successful calls cover captured-provider behavior. Track accepted/rejected counts or add deterministic synchronization if stronger test evidence is desired.
2. The new tests do not directly probe a hostile global ProxySelector or enable DNS TXT config and observe a hostile LB parser. The implementation fixes those surfaces correctly by source inspection, but their exclusion should not be described as independently exercised by this five-test suite.
3. The new provider suite uses local plaintext channels. It does not independently verify TLS certificate/authority handling, though this revision retains stock DNS/Netty authority construction rather than the resolved-once alternative which would have changed it.
4. Tests registering global providers require nonparallel execution or resource serialization across other tests touching the same registries. Current JUnit default sequential execution is compatible; do not later turn on parallel execution without addressing this shared state.
5. The owned DNS path still uses standard JVM InetAddress and, when enabled, stock JNDI TXT lookup machinery. It excludes gRPC's public resolver/proxy/LB callbacks; it does not claim to sandbox arbitrary JVM networking providers or code with reflection/bytecode instrumentation access.
